# Портфолио Амира Азизова

Сайт-портфолио frontend-разработчика: история о себе, опыте и проектах, которая
разворачивается по скроллу. Два языка — русский и английский.

## Стек

- **Next.js 16** — App Router, Turbopack, React Compiler; **React 19**
- **TypeScript 6** в строгом режиме
- **Tailwind CSS 4** и CSS Modules для сложных раскладок
- **GSAP** (ScrollTrigger, SplitText) и **Lenis** — загружаются по требованию и только там,
  где нужны
- **WebGL 2** без библиотек — дым на первом экране
- **Biome** — линтер и форматтер
- **Docker**, **Caddy** и **GitHub Actions** — сборка, HTTPS и автодеплой

## Производительность

Lighthouse, медиана пяти прогонов: на мобильном Performance 98, на десктопе 100.
Accessibility, Best Practices и SEO — 100, CLS — 0.

- Страницы пререндерятся при сборке, сервер на запрос ничего не вычисляет.
- Имя и портрет видны с первого кадра. Вступительная анимация их не прячет, и LCP не
  ждёт её окончания.
- На телефонах не загружается ни одной анимационной библиотеки. Лёгкие эффекты сделаны
  на CSS scroll-driven animations, а GSAP и Lenis подгружаются после загрузки страницы и
  только при совпадении медиазапроса: большой экран, мышь, анимации не отключены.
- Настройка анимаций ждёт простоя браузера и выполняется по одной задаче за раз, без
  длинных задач.
- Шейдер работает на половинном разрешении, 30 кадров в секунду и встаёт на паузу вне
  экрана. На телефонах показывается один статичный кадр, без GPU — CSS-градиент.
- Шрифты свои, урезаны до кириллицы, латиницы и нужных начертаний — около 70 КБ.

## Быстрый старт

Нужны Node.js 24+ (версия закреплена в `.nvmrc`) и pnpm 11.

```bash
corepack enable   # включит pnpm той версии, что указана в package.json
pnpm install
pnpm dev          # http://localhost:3000
```

Продакшен-сборка локально: `pnpm build && pnpm start`. Без `NEXT_PUBLIC_SITE_URL`
ссылки в метаданных и sitemap строятся от `http://localhost:3000`.

## Как поменять контент

- **Тексты** — `src/content/ru.ts` и `src/content/en.ts`. Оба типизированы интерфейсом
  `Dictionary`, поэтому пропущенный ключ не соберётся.
- **Контакты и статус «Открыт к предложениям»** — `src/content/site.ts`.
- **Проекты** — `src/content/projects.ts`: порядок, стек, изображения в порядке галереи
  (`screenshots`) и отдельно те, что на карточке (`cover`, от одного до трёх). Картинки
  лежат в `src/assets/projects/`, подписи к ним — в словарях.
- **Опыт** — `src/content/experience.ts`, тексты — в словарях.
- **Стек** — `src/content/skills.ts`.
- **Фото** — `src/assets/images/portrait.png`, PNG с прозрачным фоном.

Неразрывные пробелы после предлогов и перед тире расставляются автоматически
(`src/lib/text.ts`), вручную их ставить не нужно.

## Языки

Список языков — в `src/i18n/config.ts`. Язык по умолчанию задаётся одной строкой
`defaultLocale`: он открывается на `/`, остальные — по префиксу (`/en`). Адрес с префиксом
языка по умолчанию (`/ru`) перенаправляется на `/`, чтобы у каждой страницы был один
адрес. Маршрутизацию делает `src/proxy.ts`, а строки любой серверный компонент получает
через `getDictionary()`, без передачи пропсов.

## Деплой

Сайт работает на VPS в Docker Compose: контейнер `web` со standalone-сервером Next.js и
Caddy перед ним. У `web` нет опубликованных портов — снаружи открыты только 80 и 443
у Caddy. Caddy сам получает и продлевает сертификаты Let's Encrypt, перенаправляет `http`
и `www` на `https://amir-azizov.ru` и проксирует запросы на `web:3000`.

| Файл | Что делает |
| --- | --- |
| `Dockerfile` | многостадийная сборка: standalone-сервер на `node:24-alpine`, без root, с healthcheck |
| `deploy/compose.yaml` | сервисы `web` и `caddy`, тома для сертификатов и кэша картинок; тег образа — из `.env` |
| `deploy/Caddyfile` | HTTPS, редирект с `www`, HSTS, прокси на `web:3000` |
| `deploy/deploy.sh` | переключает версию через `docker compose up --wait`; если новая не стала healthy, возвращает прошлую |

Новая версия попадает на сервер так:

1. GitHub Actions собирает Docker-образ.
2. Образ уходит на сервер по SSH (`docker save | ssh … docker load`), файлы из `deploy/` —
   в `/srv/portfolio`.
3. `deploy.sh` переключает сайт на новый образ, затем workflow проверяет, что сайт отвечает.

Сервер не скачивает образ сайта ни с GitHub, ни с Docker Hub, поэтому их доступность
в России на деплой не влияет.

- `NEXT_PUBLIC_SITE_URL` — публичный адрес сайта, задаётся при сборке образа и обязателен:
  из него собираются canonical-ссылки, Open Graph и sitemap. В GitHub это переменная
  `SITE_URL` окружения `production`.
- В образе задан `HOSTNAME=0.0.0.0`, не переопределяйте его: от него зависят языковые
  rewrite-ы.

Проверить образ на своей машине — здесь порт публикуется только для локального запуска:

```bash
docker build --build-arg NEXT_PUBLIC_SITE_URL=http://localhost:3000 -t portfolio .
docker run --rm -p 3000:3000 portfolio   # http://localhost:3000
```

Без Docker: `NEXT_OUTPUT=standalone pnpm build`, затем скопировать `.next/static` и
`public` в `.next/standalone` и запустить там `node server.js`.

## CI/CD

GitHub Actions, файлы в `.github/workflows/`:

- **Pull request** — CI: Biome, TypeScript, сборка сайта и тестовая сборка Docker-образа.
- **Push в `main`** — те же проверки, затем CD: деплой на сервер, описанный выше.
  Кнопка Run workflow перевыкатывает `main` без нового коммита.

Ключ и адрес сервера (`SSH_KEY`, `SSH_HOST`, `SSH_KNOWN_HOSTS`) хранятся в секретах
окружения `production`, адрес сайта — в его переменной `SITE_URL`.
